## Known coverage limits

Recorded so nobody reads the suite as proving more than it does:

- **Plan 016's composition tests do not pin `run`'s own cross-stage order.** The six new tests drive `decide_preflight`, which is `#[cfg(test)]`; `run` never calls it, because doing so would force the USB-mode and battery PTP reads to happen even when an earlier check short-circuits before them today. Each stage's internal order is shared with production and therefore pinned, but a reordering of the stage calls *inside `run`* would still compile and pass. Closing that needs a fake transport or a device run — both deliberately out of scope.
- **Exit code 3 (state unknown) has no end-to-end test.** Both the backup-path (plan 014) and simulation-path (plan 017) classifications are unit-tested, including that tagging preserves the original error's `Display`. What no test covers is the real path: reaching it needs a camera that fails mid-restore or mid-selector-restore.
- **The Ctrl-C latch (plan 005) is unit-tested but never exercised against hardware.** A manual X-T5 check during `backup import` remains open.

## Findings considered and rejected

- Rely only on `GetDevicePropDesc`: rejected because it can constrain scalar PTP properties but cannot describe the internal RAW conversion profile field count, order, profile code, padding, or per-field logical mappings.
- Treat the latest known firmware profile as compatible with any newer version: rejected because it silently widens write support without wire evidence.
- Keep global canonical wire values and add per-firmware read aliases: rejected because the current first-value-wins serializer cannot choose a different canonical write value for different firmware.
- Raw-indexing helpers in `features/backup/artifact.rs:301-325`: verified every call site is preceded by an explicit length check; no reachable panic, not worth a plan.
- `data.get(offset..offset + 2)` without `checked_add` in `features/render/jpeg.rs:37`: input is bounded far below `usize` overflow; not exploitable.
- `build.rs` `cue export` shell-out: fixed local dev-time tool with fixed args — a supply-chain trust assumption, not a code vulnerability.
- **Write-direction PTP bulk chunk promotion** (the read side has adapted since `e283866`; `chunk_policy.write.effective_bytes` is set once and never grows, so large writes stay at the conservative initial size for the whole transfer). Deferred deliberately, not forgotten: the mechanism is easy to mirror from the read side, but the only large writes in this tool are the backup-restore payload and the RAF upload — exactly the state-changing paths where a chunk size the camera cannot handle would fail mid-transfer and produce the "camera state unknown" outcome the rest of the codebase is built to avoid. Unit tests of `ChunkPolicy` would prove nothing about that, and `AGENTS.md` requires a real-device run for hardware behavior. Revisit in a session with an X-T5 attached, validating against a full restore; do not land it on local evidence alone.

From the 2026-09-03 test-coverage audit:

- **`multiset::hash` XOR collisions** (`crates/codegen/src/util/multiset.rs:35-44`): a multiset like `{a,a}` hashes the same as `{b,b}` of equal size. Verified consistent with `multiset::eq` (multiset equality implies equal hash and length), and every use pairs the `Hash` impl with `PartialEq` backed by `eq`, so `HashMap` falls back to `eq` — collisions degrade lookup speed only, never correctness. Indirectly exercised by `ast/dnf.rs` tests (`conjunction_eq_is_multiset`, `conjunction_contains_all_respects_multiset`). No plan.
- **A standalone CUE test mechanism** (`_test.cue`, `cue vet` steps): would duplicate what the codegen schema analyses already re-validate on every build (`schema/*`, 69 tests), and a malformed CUE already fails the workspace build through `build.rs`. Not worth a plan.
- **Benchmarks (criterion)**: the CLI is USB I/O bound and codegen runs once per build; no hot path justifies the harness today. Revisit only if codegen runtime becomes a complaint.
- **Chasing a coverage percentage**: the 2026-09-03 audit mapped every module against its test inventory instead; the dangerous untested residue is exactly plans 019-022. A percentage target adds noise without naming the risk.
- Direction options not selected this round (surfaced, deliberately unplanned): uploading a per-file lcov artifact from the existing informational CI coverage job; a time-boxed cargo-mutants run over the churn hotspots (`ptp/mod.rs`, `simulation/transaction.rs`, `preflight.rs`, `cli/mod.rs`) to validate the existing corpus; a loom model of `InterruptLatch` (its five unit tests pin sequential semantics only).
